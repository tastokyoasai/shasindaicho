# 写真台帳アプリ 統合版 ver.2.2 デバッグ報告

実施日: 2026-07-28

## 総合評価

写真の大量取込、QR/OCR、作業状態の保存・復元、CSV/Excel出力、写真振り分けを単一画面にまとめた実務志向のアプリです。画像処理部品を同梱し、CSVをオフライン出力できる点、APIキーをCloudflare Worker側に分離している点、サブフォルダを含む写真識別キーを導入している点は良好です。

一方、約40万バイトの `index.html` にUI・状態管理・画像解析・出力・ファイル操作が集中しているため、変更時の回帰リスクが高く、自動テストを追加しづらい構造です。

## 修正した不具合

### 1. 角括弧を含むコピー元サブフォルダの写真を振り分けできない

コピー元フォルダを探索する際にも、保存先ファイル名向けのサニタイズ処理が適用されていました。そのため、Windowsで有効な `発掘[東]` のようなフォルダ名が `発掘東` に変化し、元写真を見つけられませんでした。

コピー元は実在する相対パスをそのまま辿り、保存先だけをサニタイズするよう修正しました。

### 2. 作業状態JSONの重複参照で写真が二重計上される

同じ写真キーが複数グループやQR写真・通常写真の両方に含まれるJSONを読み込むと、同一写真が複数の台帳行に現れる可能性がありました。また、`groups` 内に `null` 等があると例外になる経路がありました。

復元時に割当済み写真を追跡し、1枚を1回だけ割り当てるよう修正しました。不正なグループ要素は無視し、欠損件数として扱います。

### 3. `ALLOW_ORIGIN` 未設定でもOriginなしのAPI要求を処理する

文書上は `ALLOW_ORIGIN` が必須でしたが、Originヘッダーのない要求は設定が空でも先へ進めました。公開Workerの設定ミスに気づきにくく、API利用料金の悪用リスクを高めます。

許可Originが1件も設定されていない場合は、すべての要求をHTTP 500で拒否するよう修正しました。

## 実施した検証

- `index.html` のインラインJavaScript 3ブロックを構文解析
- `worker.js` をES Moduleとして構文解析
- `ALLOW_ORIGIN` 未設定時にHTTP 500となることをモック要求で確認
- `発掘[東]/区画 A` がコピー元パスとして変更されず分解されることを確認
- 修正差分の静的レビュー

ブラウザ自動操作環境のローカルファイルURL制限、およびサンプル現場写真が同梱されていないため、実写真を使うQR/OCR精度とファイルピッカーによる実コピーは未実施です。

## 改善提案

1. `index.html` を、状態管理・QR/OCR・保存復元・出力・振り分け・UIのES Moduleへ分割する。
2. 保存JSONにJSON Schema相当の厳密な検証と、復元前の「適用件数／欠損／重複」プレビューを追加する。
3. 10～20枚程度の匿名化サンプル写真と期待結果を用意し、QR検出・グループ化・CSV生成を自動回帰テストにする。
4. ExcelJSを同梱して完全オフライン化するか、CDNファイルにSRIを設定し、読み込み失敗後に再試行できるようにする。
5. Workerのレート制限に加え、App Check相当の短期トークンや利用上限監視を導入し、API費用を防御する。
6. GitHub Pages上でのCSP、`X-Content-Type-Options`、`Referrer-Policy`等のセキュリティヘッダーを配信側で設定する。

## 実データでの推奨受入試験

- デジタル看板QRと手書き看板を各5組以上
- 同名写真を異なるサブフォルダに配置
- `[]`、全角文字、空白を含むサブフォルダ名
- 保存JSONの読込を、写真取込前と取込後の両順序で実施
- 解析中断後に未解析写真が台帳へ入らないこと
- CSV/Excelを実際の業務テンプレートで開くこと
- 振り分け先に同名ファイルがある場合、上書きされないこと
